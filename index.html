File Integrity Monitor

Attackers who break into a website usually change files: a backdoor hidden in a config file, a web shell in the uploads folder, security settings switched off. This tool fingerprints every file with SHA-256 and flags anything that changes, appears or disappears. Try the simulated attack below, or check your own files. Nothing leaves your device.

    4 · Python command-line version

    For servers: the same checks from the terminal, plus a live watch mode. Baselines are interchangeable with this page.

    # create a baseline while the site is known to be clean
python python/fim.py baseline /var/www/site -o baseline.json

# later (or from cron): exit code 1 if anything changed
python python/fim.py check /var/www/site -m baseline.json

# report changes the moment they happen (pip install watchdog)
python python/fim.py watch /var/www/site -m baseline.json

    Fingerprints, not copies

    A SHA-256 hash is a 64-character fingerprint of a file's exact bytes. Change one character and about half the hash changes, so tampering can't hide. The baseline stores only hashes and sizes, never your file contents.

    Why not just timestamps?

    "Last modified" dates are easy to fake: attackers routinely reset them with commands like touch so a backdoor blends in. A hash depends only on the content, so it can't be faked without changing the file back.

    Where it's used

    File integrity monitoring is a standard control in tools like Tripwire, AIDE and Wazuh, and the PCI DSS card-payment standard requires change detection on critical files. Severity rules here flag the classic signs: scripts in upload folders and edited config files.
